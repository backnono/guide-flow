# LLM JSON 响应稳定性实施计划 v1

## 1. 目标与问题边界

当前 DeepSeek 通过 OpenAI 兼容接口返回 JSON。`response_format=json_object` 只能约束“结果是合法 JSON”，不能保证字段名称、层级、类型、枚举值和业务语义稳定。项目已经有 `DraftNormalizer` 和 `solution-draft-v1`，但仍需要把协议、校验、重试和观测规则固化为一条可验证的流水线，避免兼容逻辑继续散落到业务层。

本计划解决以下问题：

- 供应商返回包装层变化，例如 `content`、`draft`、`solutionDraft`。
- 字段别名和类型漂移，例如 `steps` 在字符串数组和对象数组之间变化。
- JSON 截断、空内容、SSE 结束原因和供应商错误被混为解析错误。
- 结构合法但内容不满足解题业务约束，仍然进入后续讲解流程。
- 解析失败时缺少原始响应、失败路径、版本和耗时，无法回放定位。
- 重试条件不够明确，导致可本地修复的问题浪费模型调用，无法恢复的问题重复调用。

本计划不把供应商字段暴露给领域层，也不承诺模型输出的数学结论天然正确。模型输出始终视为不可信外部输入。

## 2. 目标架构

```text
Prompt + JSON 输出约束
        ↓
供应商 HTTP/SSE 响应
        ↓
传输层检查（状态码、finish_reason、空内容、截断）
        ↓
供应商适配层（白名单包装、别名、类型漂移归一化）
        ↓
唯一内部协议 SolutionDraft
        ↓
Schema 格式校验
        ↓
解题业务语义校验
        ↓
必要时一次有限纠错重试
        ↓
已验证解法与个性化讲解
```

适配层是唯一允许了解 DeepSeek 字段差异的边界。Worker、Verifier、Planner、持久化和前端只依赖内部协议。

## 3. 分阶段实施

### 阶段 0：基线盘点与样本冻结

- 整理现有 DeepSeek 请求、流式响应、`DeepSeekDraftNormalizer`、`SolutionDraft` 和讲解校验器的责任边界。
- 收集数据库中的真实响应；如果没有可用生产样本，则建立最小等价样本，并标记为 synthetic。
- 为每个失败样本记录供应商、模型、Prompt 版本、Schema 版本、结束原因和错误路径。
- 明确当前默认模型、接口形态和最大输出限制，形成迁移前基线。

完成标准：已有响应形状、失败类型和当前重试行为都有可回放样本；不修改业务行为。

### 阶段 1：冻结内部协议和 Schema

- 确认 `solution-draft-v1` 的字段、类型、必填字段、空值表达和未知字段策略。
- 同步内部领域模型、JSON Schema、Prompt 示例和协议文档。
- 规定 `schemaVersion` 不匹配时的处理方式：适配层拒绝，或显式注册版本迁移器。
- 规定 `uncertainties` 的使用边界：无法确定的数学事实只能进入该字段或触发失败，不能静默猜测。

完成标准：Schema 是合法 JSON；领域模型、Prompt 和文档对字段含义一致；下游不存在供应商字段名。

### 阶段 2：拆分传输层和归一化层错误

- 为 HTTP 状态码、响应无 choices、空 content、SSE 截断、`finish_reason=length`、内容不是 JSON、字段不兼容建立可区分的错误类型。
- 保留原始响应和最后一次传输元数据，避免后续超时覆盖更有价值的解析错误。
- 将请求耗时、流式空闲超时和总超时分开记录。
- 对空内容和截断响应执行有限重试；对明确的 4xx 参数错误不重试。

完成标准：每类传输失败都能在测试中单独识别，错误不会被统一成“JSON 解析失败”。

### 阶段 3：收敛供应商适配器

- 保留 `DraftNormalizer` 作为供应商边界接口。
- 只允许遍历登记过的包装字段，并设置最大深度。
- 将可确定的字段别名、单值/数组、字符串/对象数组等类型漂移收敛到 `SolutionDraft`。
- 对多候选字段、无法判断的数学表达式和未知关键字段直接失败或写入 `uncertainties`，禁止使用“第一个字段”“最长字符串”等猜测规则。
- 每次归一化输出 `shape`、warnings 和 unknown paths，供诊断和样本扩充使用。

完成标准：所有供应商字段差异只存在于 `backend/infra/ai`；新增兼容逻辑前有失败回放测试。

### 阶段 4：增加格式与业务语义门禁

- 在进入 Solver Worker 后立即校验必填字段、数组元素类型、版本和非空要求。
- 对步骤、表达式、最终答案和不确定项执行业务语义校验。
- 确保只有验证通过的解法才进入个性化讲解计划。
- 保持讲解计划校验器对最终答案、步骤数量、视觉类型和练习答案的独立校验。

完成标准：合法 JSON 但缺字段、字段越界、答案不一致或步骤不可教时都不能进入讲解阶段。

### 阶段 5：实现有限且可观测的纠错重试

- 默认最多执行一次完整 JSON 纠错重试；上限通过配置控制，但禁止无限重试。
- 重试提示只包含结构校验失败路径、允许类型和固定协议示例，不把供应商字段扩散给业务层。
- 可在本地确定修复的问题不触发重试，例如已登记的别名和容器类型漂移。
- 无法确定的数学信息不通过重试猜测，进入失败或 `uncertainties`。
- 每次尝试记录原始响应、失败字段路径、Prompt/Schema 版本、耗时和重试原因。

完成标准：重试次数有上限、失败可解释、同一响应不会因多个兼容分支重复调用模型。

### 阶段 6：评估 DeepSeek Structured Output 路径

- 以当前生产模型和区域做最小兼容性探测，验证 DeepSeek Responses API 的 `json_schema` 是否可用。
- 验证图片输入、流式返回、结束事件、Schema 子集和错误响应，不以文档声明替代真实探测。
- 若可用，增加按供应商/模型配置的结构化输出策略；若不可用，继续使用 Chat Completions JSON Mode。
- 无论是否启用 Schema 输出，保留本地归一化、格式校验和业务校验。
- 使用灰度开关按模型启用，失败时回退到现有 JSON Mode，并记录回退原因。

完成标准：切换策略不改变内部 `SolutionDraft` 协议；结构化输出失败可安全回退且不丢失原始响应。

### 阶段 7：真实响应回放与上线门禁

- 建立真实响应 corpus，覆盖正常响应、历史包装、类型漂移、空内容、截断、非法枚举和业务语义错误。
- 执行适配层回放测试、HTTP/SSE 测试、业务校验测试和端到端讲解流程测试。
- 检查 JSON Schema 合法性、`go test ./...`、敏感字段脱敏和多图约束隔离。
- 上线前比较首次成功率、重试率、平均耗时、失败类型分布和 token 成本。

完成标准：真实问题对应的回归测试通过，AI 适配层测试通过，完整 Go 测试通过，且没有供应商字段泄漏。

## 4. 建议的小提交序列

每个提交都应保持项目可编译、可测试，并只完成一个可回滚的变化：

1. `docs: freeze llm response stability baseline`：加入样本分类和当前行为说明。
2. `test: add failing replay cases for unstable draft shapes`：先加入字段别名、类型漂移、空内容和截断失败测试。
3. `refactor: separate transport and normalization errors`：拆分传输错误与归一化错误，不改变成功路径。
4. `fix: normalize registered deepseek draft shapes`：实现已登记的本地确定性归一化。
5. `test: cover canonical solution draft schema`：补齐 Schema、版本和未知字段测试。
6. `fix: gate drafts with semantic validation`：把格式和业务语义门禁接入 Worker。
7. `fix: bound correction retries and record diagnostics`：实现一次有限纠错重试和尝试级观测。
8. `docs: document provider adapter contract`：更新供应商适配协议和故障排查说明。
9. `feat: probe deepseek structured output capability`：加入探测和配置开关，不默认切换生产流量。
10. `feat: rollout structured output with fallback`：在验证成功后按模型灰度启用，并保留 JSON Mode 回退。
11. `test: add corpus replay and end-to-end regression gate`：加入真实响应回放和上线检查。

## 5. 测试决策

测试重点是外部行为和协议边界，不测试内部递归实现细节。

- 归一化测试：输入供应商原文，断言只得到唯一的 `SolutionDraft` 或明确错误。
- 失败回放测试：每新增一个兼容分支，先验证旧实现失败，再验证修复后成功。
- HTTP/SSE 测试：覆盖非 2xx、空 content、`length` 截断、正常结束和流式空闲超时。
- 语义校验测试：覆盖缺步骤、答案不一致、不确定项处理和不可教解法。
- 重试测试：断言本地可修复漂移不重试，结构失败最多按配置重试，4xx 不重试。
- 追踪测试：断言原始响应、失败路径、版本、结束原因和耗时被保留。
- 集成测试：验证只有已验证解法才能生成讲解，供应商字段不出现在领域层和 API 层。
- Schema 测试：验证 `docs/schemas/solution-draft.schema.json` 是合法 JSON，且与内部协议同步。

## 6. 决策记录

- 当前内部协议继续使用 `solution-draft-v1`，不直接照搬 DeepSeek 响应。
- Chat Completions JSON Mode 作为兼容基线；Structured Output 只有在当前模型和区域探测通过后才灰度启用。
- 适配层允许有限白名单兼容，不允许通用递归猜字段。
- 本地可确定归一化优先于模型重试；重试只处理本地无法恢复且可能由模型修正的结构错误。
- 结构校验和数学业务校验必须同时保留。
- 原始响应用于回放和诊断，进入日志或数据库前必须按现有敏感信息策略处理。

## 7. 明确不在范围内

- 不在本计划中重写题目识别、OCR 或几何语义模型。
- 不把所有供应商统一成一个无法表达差异的通用 SDK。
- 不通过增加 Prompt 长度替代本地校验。
- 不允许无限重试或把失败响应直接展示为可信答案。
- 不在没有真实兼容性探测前强制迁移到 Responses API 或 JSON Schema。
- 不因单道题增加点名、坐标或图形特判。

## 8. 执行方式

实施时按阶段顺序推进。每完成一个小提交，先运行该阶段规定的测试并检查 `git diff`，再进入下一阶段。任何新响应形状都必须先加入失败回放样本，再修改适配器。若某阶段发现协议需要变化，应先更新本计划、Schema、Prompt、适配器和测试的变更清单，再继续编码。
