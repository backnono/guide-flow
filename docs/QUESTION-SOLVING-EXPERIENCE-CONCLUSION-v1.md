# 题目解析与讲解体验方案结论 v1

## 1. 决策结论

当前阶段不再把“自动复现题目图形”作为题目确认和后续解题的必要步骤。

用户上传的原图是几何图形的唯一可信来源。系统可以继续解析题干、问题目标、已知条件和点线关系，但自动生成的图形只允许作为可选的辅助示意，不能替代原图，也不能阻塞解题流程。

核心流程调整为：

```text
原图 + OCR
    ↓
题干、已知条件和小问确认
    ↓
基于原图和结构化题面的解题
    ↓
可选：检索相似题或原题解答作为参考
    ↓
LLM 生成讲解教程
```

## 2. 背景与问题

几何图形的自动复现存在较高的不确定性，尤其集中在：

- 点在线段、直线或延长线上的归属；
- 多图题中图 1 和图 2 的关系隔离；
- 圆、半圆、圆弧的端点、圆心和上下方向；
- 交点、共线、垂直和平行关系；
- 示意图坐标与真实数学约束之间的区别。

当前实现即使能够生成结构完整的 SVG，也可能在视觉上看似合理、数学拓扑却已经错误。错误重绘比不展示重绘结果更容易误导用户。

因此，自动重绘不应成为用户确认题目和进入讲解的前置条件。

## 3. 产品体验方案

### 3.1 题目确认页

确认页以原图为主，解析内容为辅：

1. 展示用户上传的原始题目图片。
2. 展示 OCR 后的完整题干。
3. 展示识别到的小问、已知条件和关键关系。
4. 展示无法确认的内容，例如“某点是否位于延长线上”。
5. 提供“重新解析”和“确认题目，开始讲解”两个主要操作。

自动重绘图默认不展示，避免用户把示意图误认为原题图。

### 3.2 几何题展示

几何题后续讲解始终携带原图。若系统生成辅助图，必须：

- 明确标注“辅助示意图”；
- 不宣称其比例、角度或位置与原图一致；
- 不把辅助图作为数学事实来源；
- 当图形结构置信度不足时直接隐藏；
- 即使辅助图生成失败，也不能阻塞解题。

### 3.3 非几何题展示

函数题、应用题和算术题不生成 `diagram.figures`。它们直接使用：

- 完整题干；
- 已知量及单位；
- 问题目标；
- 公式、变量和约束；
- 原始图片作为回溯依据。

## 4. 解题输入协议

后续 LLM 不应只接收重绘后的结构化图形，而应接收以下组合输入：

```text
原始题目图片
正式题干
题型
已知条件
问题目标
结构化点线关系（如有）
不确定项
```

对于几何题，原图优先级最高；结构化点线关系只作为辅助索引。若原图、题干和结构化关系存在冲突，系统必须优先提示用户确认，而不是自行选择一套关系继续推理。

## 5. 公网检索策略

公网检索可以作为辅助能力，但不能作为默认答案来源。

### 5.1 推荐用途

系统可以根据以下信息检索相似题或原题解答：

- 完整题干中的独特句子；
- 题号、年份和地区；
- 已知条件组合；
- 小问目标；
- 关键公式或几何关系。

### 5.2 检索结果使用规则

搜索结果必须经过二次核对：

1. 题干是否一致；
2. 小问数量是否一致；
3. 图形关系是否一致；
4. 数值和单位是否一致；
5. 解答是否引用了原题中不存在的条件。

不允许因为搜索结果存在，就直接跳过原图分析或直接复制答案。检索结果应作为 `researchContext` 或候选解答，交给 LLM 做一致性判断和教程重写。

### 5.3 检索失败时的降级

如果公网无法找到可靠匹配，系统仍应基于原图、正式题干和结构化信息生成解题方案。公网检索失败不能导致题目失败。

## 6. 技术边界

### 6.1 仍然保留的能力

- 原图上传和原始响应留档；
- OCR 正式题干提取；
- 题型识别；
- 已知条件和问题目标提取；
- 几何点线关系提取；
- 不确定项记录；
- 有限纠错重试；
- 原图回放和结构化响应校验。

### 6.2 降级为可选的能力

- 自动生成 SVG 图；
- 圆弧和半圆的示意绘制；
- 由结构化关系推导示意坐标；
- 根据视觉比例生成布局。

这些能力只能服务于辅助理解，不能进入解题事实链路。

### 6.3 禁止的行为

- 用重绘图替代用户原图；
- 根据视觉比例猜测数学坐标；
- 在点线关系不确定时自动补造关系；
- 将搜索到的相似题答案视为当前题答案；
- 因为重绘失败而阻塞题目确认或讲解。

## 7. 推荐状态流转

```text
uploaded
  ↓
recognizing
  ↓
awaiting_confirmation
  ├─ 用户确认 → solving
  ├─ 用户要求重新解析 → recognizing
  └─ 解析文本不完整 → 用户补充图片或文字
```

图形辅助渲染属于旁路状态，不改变主流程：

```text
structuredQuestion
  ↓
尝试生成辅助示意图
  ├─ 高置信度 → 可展示“辅助示意图”
  └─ 低置信度/失败 → 隐藏，不影响 solving
```

## 8. 分阶段实施计划

### 阶段一：先优化用户体验

- 确认页默认隐藏自动重绘图；
- 保留原图展示；
- 展示题干、小问、已知条件和不确定项；
- 允许用户直接确认并开始讲解；
- 重绘失败不再阻塞主流程。

### 阶段二：优化解题链路

- 将原图作为解题 LLM 的固定输入；
- 将结构化解析结果作为辅助上下文；
- 几何题发生冲突时明确提示用户；
- 将“图形复现失败”和“题目解析失败”分开统计。

### 阶段三：增加检索增强

- 基于题干生成检索查询；
- 保存候选网页、题目匹配度和来源；
- 对候选答案执行题干和图形关系核对；
- 只把通过核对的候选内容交给 LLM 重写教程。

### 阶段四：保留可选辅助图

- 仅在点线关系完整且置信度足够时显示；
- 明确标记为辅助示意图；
- 增加圆弧方向、交点和多图隔离的回归测试；
- 辅助图只服务于讲解，不参与事实判定。

## 9. 成功指标

后续优化不再以“重绘图完整率”作为第一指标，而应关注：

- 用户确认题干的成功率；
- 用户从上传到开始讲解的完成率；
- 用户主动重新解析的比例；
- 解题教程被用户接受或继续追问的比例；
- 几何题错误关系进入解题链路的比例；
- 检索候选被判定为可靠答案的比例；
- 因辅助图失败导致的流程阻塞次数，应为零。

## 10. 最终决策

当前产品优先级确定为：

1. 正确识别题干和问题目标；
2. 保留并展示原始题目图片；
3. 基于原图和结构化信息完成解题；
4. 通过公网检索增强答案，但必须进行一致性核对；
5. 将自动复现图形降级为可选辅助能力。

自动复现图形不是当前产品交付的必要条件。只有当图形协议、语义校验和渲染方向都足够稳定后，才逐步恢复其展示范围。
