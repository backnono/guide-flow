# 题目检索与 LLM 教程生成方案 v1

## 1. 方案结论

当前系统不应把“LLM 独立推导完整解答”作为唯一解题路径。

对于复杂几何题、综合题和有明确年份/地区/题号的题目，优先通过公网或题库检索原题及参考解答，再由 LLM 基于原图、确认后的题面和检索证据生成适合用户的讲解教程。

核心原则：

1. 搜索和教程生成是前后依赖的两个阶段，不并行执行。
2. 搜索失败时不调用 LLM 教程生成，快速结束并记录搜索失败。
3. 搜索成功后立即持久化参考解答，用户可以直接阅读，不必等待教程。
4. LLM 教程必须使用检索到的结果作为参考，但不能直接复制搜索内容。
5. 搜索内容、供应商响应和 LLM 输出都属于不可信输入，必须经过本地归一化、题目匹配和业务校验。
6. 教程生成失败不能清除已经找到的参考解答；用户可以只重试教程生成。

## 2. 用户体验目标

用户上传题目并确认题面后，系统应尽快给出可用结果：

```text
上传原图
  ↓
OCR 与题目确认
  ↓
搜索原题和参考解答
  ├─ 搜索失败：提示未找到可靠参考，不调用 LLM
  └─ 搜索成功：立即展示参考解答
                    ↓
              用户是否需要讲解
                    ├─ 否：结束
                    └─ 是：LLM 生成教程
```

参考解答和 LLM 教程需要在前端分层展示：

### 2.1 参考解答

适合已经能够自行理解标准步骤的用户，展示：

- 匹配到的原题信息；
- 参考答案或解题步骤；
- 来源标题和链接；
- 题干、小问、图形关系的匹配结果；
- 参考内容的可信度和核对状态；
- “外部参考，尚未生成个性化讲解”的状态提示。

### 2.2 我的讲解

适合需要理解过程的用户，展示：

- LLM 根据原图和确认题面生成的分步教程；
- 关键几何关系或计算关系；
- 每一步为什么成立；
- 参考解答与生成教程之间的差异；
- 不确定项和需要用户确认的内容。

如果搜索已经找到可靠参考，用户可以直接结束，不需要等待 LLM。

## 3. 推荐状态流转

当前 `structuring` 中隐式执行搜索的方式不足以支持前端分阶段展示，应把搜索和教程生成视为独立阶段。

推荐状态：

```text
awaiting_confirmation
  ↓ 用户确认
researching
  ├─ search_failed / research_unavailable
  └─ research_ready
          ↓ 用户请求讲解
      teaching
          ├─ tutorial_failed
          └─ ready
```

如果暂时不扩展主状态机，也至少要在 Lesson 内增加明确的阶段字段：

```text
researchStatus: not_started | searching | unavailable | found | verified | conflict
tutorialStatus: not_started | generating | failed | ready
```

两者必须独立保存，不能继续统一映射成 `stage_failed`。

### 3.1 搜索失败

搜索超时、网络错误、来源无法访问或没有匹配结果时：

- 不调用 LLM 教程生成；
- 保存 `research_unavailable` 或 `conflict`；
- 记录搜索错误码和耗时；
- 前端提示“未找到可靠参考解答”；
- 是否允许回退到直接 LLM 解题，应由产品策略明确决定，不能静默发生。

对于本方案的复杂几何题，默认不回退，避免再次触发长时间的无证据推导。

### 3.2 搜索成功

搜索通过题目匹配后：

- 立即保存 `ResearchContext` 和候选参考解答；
- 前端立即展示参考解答；
- 不自动强制调用 LLM；
- 用户点击“生成讲解”后才进入 `teaching`。

### 3.3 教程失败

LLM 超时、返回格式错误或教程校验失败时：

- 保留已保存的参考解答和来源；
- `tutorialStatus=failed`；
- 只允许重试教程生成；
- 不重新搜索，除非用户主动要求刷新参考资料；
- 前端显示“参考解答已找到，但讲解暂时生成失败”。

## 4. 搜索策略

### 4.1 触发条件

以下题目默认进入搜索优先路径：

- 复杂几何证明；
- 多问综合题；
- 竞赛题、压轴题或中考试题；
- 题干包含年份、地区、试卷名称或题号；
- 当前结构化题型为 `geometry_numeric`，但包含证明、旋转、相似、延长线、交点等复杂关系；
- 用户明确要求查找标准答案或网上解法。

基础算术题、简单方程和低风险题目可以继续采用直接解题路径。

### 4.2 查询词生成

查询词必须基于确认后的正式题面，而不是只依赖 `questionAnalysis`。至少包含：

- 题干中的独特句子；
- 年份和地区；
- 题号；
- 关键点线关系；
- 小问目标。

当 OCR 存在缺字时，应优先使用用户确认后的文本，并结合结构化关系生成多个查询变体。不得凭空补造数学条件。

### 4.3 来源核对

搜索结果必须逐项核对：

1. 题干是否一致；
2. 小问数量是否一致；
3. 图形中的点、线和交点关系是否一致；
4. 数值、单位和角度是否一致；
5. 解答是否引用原题不存在的条件。

匹配失败的结果只能标记为“相似题参考”，不能作为当前题标准答案。

## 5. 内部数据协议

现有 `ResearchContext` 只保存来源摘要，无法充分支持教程生成。建议增加候选参考解答，但仍必须与供应商响应隔离：

```json
{
  "query": "2020 福建 几何3 旋转90度 AD EC 相交于P EP/PF=PC/CF",
  "status": "verified",
  "sources": [
    {
      "title": "来源标题",
      "url": "https://example.com/source",
      "summary": "与当前题目匹配的题干和解题摘要",
      "trustScore": 0.92
    }
  ],
  "matchedQuestion": {
    "title": "2020年福建省中考数学第24题",
    "matchScore": 0.97,
    "matchedSubquestionCount": 2,
    "checks": [
      "题干匹配",
      "图形关系匹配",
      "小问数量匹配"
    ]
  },
  "referenceSolution": {
    "status": "candidate",
    "steps": [
      "参考步骤一"
    ],
    "finalAnswer": "参考结论",
    "uncertainties": []
  },
  "retrievedAt": "2026-10-20T10:00:00Z"
}
```

说明：

- `referenceSolution` 是统一内部协议，不是搜索供应商原始结构；
- 供应商字段别名、类型漂移和网页结构差异只能在 `backend/infra/ai` 或搜索 Adapter 中处理；
- 领域层和前端不得依赖供应商原始字段；
- 搜索摘要和参考答案必须保留来源 URL，便于审计和用户查看。

## 6. LLM 教程输入

教程生成的输入必须包括：

```text
原始题目图片
确认后的正式题干
题型和小问
已知条件
点线关系和不确定项
已通过核对的参考解答
参考来源
```

LLM 的任务不是重新搜索，也不是盲目从零推导，而是：

1. 判断参考解答是否与当前题面一致；
2. 发现参考解答与原图或题干冲突时标记冲突；
3. 将可靠步骤改写成适合当前用户的教程；
4. 给出每一步的依据；
5. 不得把搜索内容未经核对直接复制为最终答案。

## 7. 超时与重试

搜索和教程生成是依赖关系，但超时统计必须独立：

```text
researchDurationMs / researchErrorCode
tutorialDurationMs / tutorialErrorCode
```

建议初始配置：

- 搜索超时：8～15 秒；
- 搜索重试：0～1 次；
- 教程生成超时：根据模型能力设置，不与搜索超时共用；
- 教程重试：由用户主动触发，且只重试教程阶段。

不得用一个泛化的 `stage_failed` 覆盖搜索失败、教程超时、响应解析失败和业务校验失败。

## 8. 后端模块调整

当前代码已经有 `SearchAdapter` 和 `ResearchRouter`，可以作为实现起点，但需要调整：

1. `ResearchRouter` 能根据 `StructuredQuestion` 判断复杂几何题，而不只依赖空的 `QuestionAnalysis`。
2. 生成查询时使用 `Question.NormalizedText` 作为兜底。
3. `SearchAdapter` 返回统一的研究上下文和候选参考解答。
4. 搜索完成后先持久化，再允许前端读取参考解答。
5. 教程生成接口接收已核对的 `ResearchContext`。
6. 教程重试接口只重新执行 LLM 生成，不重复搜索。
7. 增加搜索阶段和教程阶段的追踪记录、耗时、错误码和请求 ID。
8. 增加搜索供应商不可用、题目不匹配、教程超时和教程解析失败的回归测试。

后端不能直接依赖当前对话中的浏览器搜索工具。运行时需要接入真实的搜索服务或内部搜索代理，并通过 `SearchAdapter` 隔离供应商协议。

## 9. 前端接口建议

前端根据状态分别展示：

```text
researchStatus=searching
  “正在查找这道题的参考解答”

researchStatus=verified
tutorialStatus=not_started
  展示参考解答
  按钮：生成我的讲解

tutorialStatus=generating
  参考解答继续可见
  展示：正在根据参考解答生成讲解

tutorialStatus=failed
  参考解答继续可见
  展示：讲解生成失败
  按钮：重试生成讲解

tutorialStatus=ready
  同时展示参考解答和我的讲解
```

参考解答必须有明显的“外部参考”标识；教程必须有“AI 生成并经过本地校验”的状态说明。

## 10. 验收标准

### 搜索链路

- 复杂几何题能够进入搜索阶段；
- 查询词不为空，且包含确认后的题干信息；
- 搜索超时不会调用 LLM；
- 搜索成功后能立即读取参考解答；
- 题目不匹配的搜索结果不会被标记为当前题答案。

### 教程链路

- 教程生成请求包含原图、正式题面和已核对参考解答；
- 教程超时不会清除参考解答；
- 教程重试不会重复搜索；
- 搜索和教程拥有独立错误码、耗时和追踪记录；
- 教程仍需经过现有数学语义校验。

### 前端体验

- 用户可以只阅读参考解答并结束；
- 用户可以主动生成个性化教程；
- 教程生成失败时不会回退为“题目识别失败”；
- 原图始终是几何事实的主要来源。

## 11. 与现有方案的关系

本方案继承以下既有约束：

- 原图优先，自动重绘图只作为辅助；
- 供应商响应必须经过适配层归一化；
- 搜索结果不能直接成为最终答案；
- 几何关系需要本地语义校验；
- 多图关系不得串图；
- 所有外部调用必须有限、可观测、可重放。

本方案对既有“公网检索作为可选能力”的调整是：

- 对复杂几何题和明确的考试题号，检索改为默认优先；
- 搜索成功后，参考解答成为独立的用户可见结果；
- LLM 教程生成改为搜索结果之后的可选步骤，而不是搜索和 LLM 必须一次性完成的单一任务。
